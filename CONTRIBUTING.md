# Contributing

Thanks for helping! `wbh` aims to stay small: one binary, offline, no accounts. Please open an issue before starting large features; [the implementation plan](WRITTEN_BY_HAND_IMPLEMENTATION_PLAN.md) lists what is deliberately out of scope.

## Develop

```sh
cargo fmt
cargo clippy --all-targets --all-features -- -D warnings
cargo test --all-targets
```

CI runs the same commands on macOS, Linux and Windows, and checks the minimum supported Rust version (1.88).

**Badge changes:** the README gallery (`docs/badges/`), the gallery site's badges (`site/badges/`) and its manifest (`site/badges.js`) are all generated by the renderer, and a test fails if any is stale. After changing `src/badge.rs`, regenerate them and look at the result in a browser, on both light and dark backgrounds:

```sh
WBH_BLESS=1 cargo test gallery
```

**Never delete or rename files in `site/badges/`.** Their URLs are pasted in other people's READMEs. Add new labels to `INSTANT_LABELS` in `src/badge.rs` instead.

**Gallery site:** `site/` is plain HTML, CSS and JS with no build step. Preview it with `python3 -m http.server -d site` and check it at phone width, in dark mode, and with the keyboard.

**Examples:** `examples/*` are checked by `wbh check` in the test suite. After changing outputs, regenerate them:

```sh
for d in examples/*/; do cargo run -q -- --root "$d" scan; done
```

## Ground rules

- Never describe handwritten status as verified or detected. It is self-declared, and unmarked code is "unmarked", not "AI-written".
- Normal commands make no network requests and never modify source files.
- Generated output must be byte-identical for identical input: no timestamps, no unstable ordering.

## Releasing

1. Bump `version` in `Cargo.toml` and move the `CHANGELOG.md` entries under the new version.
2. Commit, then tag and push: `git tag v0.5.0 && git push origin v0.5.0`.
3. The Release workflow builds every target and creates a **draft** GitHub release with archives and checksums. Review it, then publish.
4. Publish to crates.io: `cargo publish`. Do this after the GitHub release is public, because `cargo binstall` downloads its archives.
