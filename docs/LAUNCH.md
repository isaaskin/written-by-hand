# Launch checklist and drafts

Nothing here gets posted automatically. Every post is a human decision.

## Before launch

The repository is `github.com/isaaskin/written-by-hand`, and the gallery lives at `https://isaaskin.github.io/written-by-hand/`. **Don't rename or move the repo after launch:** gallery badge URLs end up in other people's READMEs, and a rename breaks all of them.

1. Push, then in the repository settings:
   - **Pages → Source: GitHub Actions.** The Pages workflow publishes `site/`.
   - **General → Social preview:** upload `site/social-preview.png`.
   - **About:** use the description below, the gallery URL as the website, and the topics `rust`, `cli`, `developer-tools`, `github-readme`, `badge`, `open-source`.
2. Tag the first release (see CONTRIBUTING.md), publish the draft release, then run `cargo publish`.

## Launch gate

All of these should be true before any public post:

- [ ] A badge copied from the live gallery renders in a real GitHub README, in light and dark mode.
- [ ] That badge links back to the live gallery.
- [ ] The gallery works on a phone, and Copy Markdown works in at least Chrome, Firefox and Safari.
- [ ] Following the README from a clean machine, someone can download `wbh` for each advertised platform and get a badge plus `REPORT.md` with `wbh init`, `wbh mark` and `wbh scan`.
- [ ] No placeholders or local addresses remain in user-facing files.
- [ ] At least one person who didn't build this has followed the instructions without help.
- [ ] Every post below describes only what has shipped.

## Show HN

Check the current Show HN guidelines first. Don't ask anyone to upvote.

**Title:** Show HN: Written by Hand – A tiny badge for human-written code

**First comment:**

> I made Written by Hand as a small developer-culture joke. You can copy a badge straight into a GitHub README from a static gallery, or use a Rust CLI to mark the files and blocks you wrote yourself (`// @handwritten:start` … `// @handwritten:end`) and generate a report of the declared line ranges.
>
> It doesn't detect AI and it doesn't prove anything. The declarations are voluntary, and unmarked code is just unmarked. That's the point.
>
> I wanted it tiny: static SVG badges, a single offline binary that never edits your source, and no accounts or tracking. I'd especially like feedback on the badge designs and on whether setup is as simple as it should be.

## DEV article outline

**"I built a ridiculous Rust tool to stamp my handwritten code"**

1. The joke, and why a badge rather than a detector.
2. What "self-declared" means, and why verification was left out on purpose.
3. The zero-install gallery: static files, generated by the same renderer as the CLI.
